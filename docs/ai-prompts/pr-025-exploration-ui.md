# PR #25: 탐험 캐릭터·쓰레기 연출 및 효과음 개선

## 개요

- 브랜치: `feature/exploration-ui`
- PR: #25
- 작성일: 2026-08-07
- 작업 목적: 탐험 화면의 캐릭터와 쓰레기 더미 표현을 개선하고 이동·수집·QTE에 상황별 효과음을 적용한다.

## 주요 요청

1. 임포트된 캐릭터 에셋을 탐험 로봇에 적용하고 이동 방향과 도착 방향을 표현한다.
2. 쓰레기 더미 종류별 이미지를 다양하게 표시하고 화면 크기를 조정한다.
3. 이동 및 수집 과정에 어울리는 효과음을 적용하고 재생 타이밍과 음량을 조정한다.
4. QTE 실패·성공·대성공을 구분하는 효과음을 만들고 판정 영역과 UI를 조정한다.

## AI와 논의한 내용

### 캐릭터와 쓰레기 더미 표현

기존 프리팹과 임포트된 스프라이트 구성을 확인한 뒤 로봇의 이동 방향별 애니메이션을 연결했다. 로봇이 쓰레기에 도착하면 마지막 이동 방향이 아니라 쓰레기가 있는 방향을 바라보도록 결정했다. 쓰레기 더미는 종류별 후보 이미지 중 하나를 무작위로 선택하되 프리팹 크기를 조정해 화면 비율을 맞췄다.

### 탐험 효과음 구성

이동음은 별도의 마무리 구간을 재생하지 않고 로봇이 이동하는 동안 반복하고 도착 시 즉시 정지하도록 단순화했다. 수집음은 세 파일 중 직전 파일을 피해서 무작위 재생하며, 첫 번째 파일의 앞쪽 무음은 시작 위치를 보정했다. QTE 결과음은 기존 감정 효과음 재사용을 중단하고 실패·성공·대성공이 구분되는 짧은 전용 WAV 파일을 생성했다.

### QTE 판정과 UI

런타임 로그로 스페이스바 입력이 전달되는지, 입력 시 바늘 각도와 판정 범위가 어떻게 계산되는지 확인했다. 결과 판정을 단일 메서드로 정리하고 시간 초과 여부를 포함한 진단 로그를 추가했다. 고정 호 형태의 UI 에셋은 Radial Fill로 자르면 형태가 깨지므로 원본을 그대로 표시하고, 에셋의 시각적 폭에 맞춰 실제 성공 및 대성공 판정 범위를 함께 넓혔다.

## 주요 결정

- 로봇 애니메이션과 오디오는 기존 플레이어 프리팹에 작은 전용 컴포넌트로 연결한다.
- 쓰레기 더미 이미지는 스폰 시 무작위 선택하되 쓰레기 종류별 후보 목록을 유지한다.
- 이동음은 이동 중 반복하고 도착 시 즉시 정지한다.
- 수집음은 세 후보를 무작위 재생하고 직전 음원의 연속 재생을 피한다.
- QTE 결과음은 실패·성공·대성공 전용 음원을 각각 사용한다.
- QTE 속도는 180도/초, 성공 범위는 110도, 대성공 범위는 70도로 조정한다.

## 검증 내용

- 로봇 이동 방향별 스프라이트 전환과 쓰레기 도착 시 방향 전환을 확인했다.
- 쓰레기 종류별 이미지 후보와 프리팹 참조를 확인했다.
- 이동 시작·도착 이벤트 및 수집 시작·QTE 종료 이벤트와 효과음 연결을 확인했다.
- QTE 결과별 이벤트와 서로 다른 전용 음원 GUID 연결을 확인했다.
- 런타임 QTE 로그에서 스페이스바 입력, 시간 초과, 바늘 각도 및 판정 범위 출력을 확인했다.
- `git diff --check`로 변경 파일의 공백 오류가 없음을 확인했다.
- 일반 .NET 빌드는 로컬에 .NET Framework 4.7.1 타기팅 팩이 없어 수행하지 못했으며, Unity 에디터 런타임 로그에서 스크립트 실행을 확인했다.

## AI 사용 범위

사용자가 에셋과 사운드의 방향, 크기, 음량 및 재생 방식을 반복해서 확인하고 최종 기준을 결정했다. AI는 기존 Unity 구조 분석, 컴포넌트 구현, 씬과 프리팹 연결, 절차적 QTE 효과음 생성, 런타임 로그 분석과 Git 작업을 지원했다.
