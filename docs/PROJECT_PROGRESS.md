# CleanPlanet 프로젝트 진행 현황

> 기준: 2026-08-04, `origin/main` (`c53c5c8`)  
> 이 문서는 저장소의 코드, 씬, 에셋, 병합된 PR과 AI 협업 기록을 기준으로 정리한 스냅샷이다.

## 한눈에 보기

현재 프로젝트는 핵심 기능을 각각 시연할 수 있는 프로토타입 단계다. 그리드 기반 이동, 수집물 감정과 재화 지급, 베이스 화면 전환, 업그레이드 스킬 트리 UI가 구현되어 있다. 다만 이 기능들이 하나의 완전한 게임 루프로 연결되지는 않았으며, 쓰레기 수집·재활용, 실제 업그레이드 구매, 저장과 불러오기는 아직 구현되어 있지 않다.

## 개발 환경

- Unity `6000.5.6f1`
- Universal Render Pipeline `17.6.0`
- Input System `1.20.0`
- 2D 탑다운 방치형·증분형 게임
- 주요 씬: `SampleScene`, `BaseScene`, `GameScene`
- Build Settings 등록 씬: `SampleScene`, `BaseScene`
  - `GameScene`은 저장소에 존재하지만 현재 Build Settings에는 등록되어 있지 않다.

## 시스템별 상세

### 그리드와 이동

- `GridSystem`이 월드 좌표와 셀 인덱스 변환 및 범위 검사를 담당한다.
- `GridOccupancy`가 셀당 하나의 오브젝트만 점유하도록 관리한다.
- `TargetCellSelector`가 점유된 대상을 클릭했을 때 상·우·하·좌 순서와 Manhattan Distance를 기준으로 가장 가까운 빈 인접 셀을 고른다.
- `GridPathfinder`가 점유 셀을 피해 4방향 최단 경로를 계산한다.
- `PlayerMovement`가 경로를 셀 단위로 이동하며, 이동 중 다음 셀이 선점되면 직전 셀로 복귀한 뒤 재탐색한다.
- `PlayerClickToMove`가 Input System의 마우스 입력을 목적지 결정과 연결한다.
- 현재 생성과 연결은 `GridOccupancyTester`에 의존하는 테스트 구조이며 정식 게임 부트스트랩은 없다.

### 감정과 재화

- `CollectibleData` ScriptableObject와 16개의 더미 수집물 데이터가 있다.
- `AppraisalCore`가 가중치 기반으로 `x1`, `x2`, `x4`, `x8`, `x16` 배수를 결정한다.
- `AppraisalTank`, `AppraisalReelSequencer`, `AppraisalDisplay`가 수집물 투입부터 릴 정지와 지급 확정까지의 연출을 담당한다.
- `AppraisalDriver`가 확정된 지급액을 `CurrencyWallet`에 더한다.
- 지급액은 6개 티어로 분류되며 코인 수, 사운드, 화면 흔들림, 플래시와 배너 연출이 달라진다.
- 티어 설정은 `AppraisalTierTable.asset`에서 관리한다.
- `BaseScene`에 감정 패널, 재화 HUD, 효과 디렉터와 티어별 디버그 UI가 배선되어 있다.

### 베이스 화면과 업그레이드 UI

- `BaseViewController`가 감정 로봇 패널과 업그레이드 패널의 탭 전환을 담당한다.
- 스킬 트리는 마우스 드래그 이동, 휠/UI 버튼 확대·축소, 화면 맞춤 배율과 초기화를 지원한다.
- 16개 노드를 선택하면 상태, 이름, 분류, 설명, 현재 효과, 다음 효과와 비용이 상세 패널에 표시된다.
- 노드 데이터는 현재 `BaseScene`에 직렬화된 표시용 데이터다. 별도 업그레이드 데이터 모델이나 구매 로직은 없다.

## 씬과 콘텐츠 상태

### `BaseScene`

현재 가장 완성도가 높은 시연 씬이다. 다음 요소가 포함되어 있다.

- 감정 로봇과 릴 UI
- 골드 지갑과 HUD
- 감정 티어 이펙트 및 디버그 패널
- 감정/업그레이드 탭 전환
- 16노드 업그레이드 스킬 트리와 상세 패널

### `GameScene`

그리드 점유, 목표 셀 선택, 경로 탐색과 클릭 이동을 시험하기 위한 씬이다. 테스트용 `GridOccupancyTester` 중심으로 구성되어 있으며 Build Settings에는 아직 포함되지 않았다.

### `SampleScene`

Build Settings의 첫 씬으로 등록되어 있다. 프로젝트의 최종 시작 흐름이 확정되면 유지 여부와 시작 씬 순서를 재검토할 필요가 있다.

## 확인된 검증 기록

- 그리드 좌표 변환 자체 테스트: 10/10 통과
- 목표 셀 선택 자체 테스트: 5/5 통과
- 경로 탐색 자체 테스트: 5/5 통과, 50×50 테스트 기록 포함
- Play Mode에서 셀 중심 이동, 점유 갱신, 이동 중 선점 후 재탐색 확인 기록
- Unity 에디터에서 감정 → 지급 → 티어 이펙트 흐름 확인 기록
- Unity 에디터에서 스킬 트리 탐색 및 노드 상세 표시 확인 기록

위 결과는 병합된 PR의 수동 검증 기록이다. 현재 저장소에는 Unity Test Framework용 독립 테스트 어셈블리나 CI 테스트 구성이 없다.

## 주요 기술 부채와 위험

1. 핵심 게임 루프가 분리되어 있다. 그리드 이동, 감정, 재화와 업그레이드 UI가 각각 동작하지만 `탐색 → 쓰레기 수집 → 감정/재활용 → 재화 → 업그레이드 → 성장` 흐름은 아직 연결되지 않았다.
2. 쓰레기 수집 기반 코드가 현재 없다. `PlayerTrashCollector`, `TrashInventory`, `TrashItem`, `TrashSpawner`는 그리드 이동 작업 과정에서 삭제되었다.
3. 업그레이드는 표시 전용이다. 구매 가능 여부, 비용 차감, 효과 적용, 선행 조건과 데이터 저장이 없다.
4. 테스트 기반이 수동 도구에 집중되어 있다. 리팩터링 시 회귀를 자동으로 탐지하기 어렵다.
5. `GameScene`이 Build Settings에 빠져 있고 `SampleScene`이 첫 씬이다. 데모 실행 경로를 명확히 정할 필요가 있다.
6. 코인 이펙트처럼 많은 오브젝트를 생성하는 기능은 실제 플레이 빈도가 높아질 경우 오브젝트 풀링 적용 여부를 측정해야 한다.

## 권장 다음 작업 순서

1. 데모의 시작 씬과 최소 플레이 루프를 확정한다.
2. 테스트용 그리드 부트스트랩을 정식 게임 초기화 구조로 분리한다.
3. 쓰레기 생성·수집·인벤토리를 그리드 이동과 다시 연결한다.
4. 인벤토리의 수집물을 감정 로봇 입력으로 연결한다.
5. 업그레이드 데이터와 구매/골드 차감/효과 적용을 구현한다.
6. 재화와 업그레이드 진행도의 저장/불러오기를 추가한다.
7. 핵심 순수 로직부터 Edit Mode 자동화 테스트로 이전한다.
8. Build Settings와 데모 빌드를 정리하고 전체 플레이 흐름을 검증한다.
