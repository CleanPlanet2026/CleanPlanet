## 프로젝트 요약

CleanPlanet은 Unity 6 URP 기반의 2D 탑다운 방치형·증분형 게임이다. 플레이어는 탐험에서 쓰레기를 수집하고, 베이스에서 수집물을 감정해 골드를 획득한 뒤 로봇을 업그레이드한다.

현재 타이틀 → 탐험 → 수집/QTE → 베이스 복귀 → 감정/골드 → 업그레이드 → 재탐험으로 이어지는 핵심 게임 루프가 연결돼 있다. WebGL 자동 빌드와 GitHub Pages 배포도 `main` 기준으로 구성돼 있다.

## 개발 및 배포 환경

- Unity `6000.5.6f1`
- Universal Render Pipeline `17.6.0`
- Input System `1.20.0`
- 빌드 씬 순서: `TitleScene`, `BaseScene`, `GameScene`
- WebGL CI/CD: `.github/workflows/deploy-webgl.yml`
- 배포 조건: `main` push 또는 수동 실행
- 배포 대상: GitHub Pages

## 현재 게임 흐름

1. `TitleScene`에서 새 탐험을 시작한다.
2. 베이스에 도달한 저장 기록이 있으면 타이틀에서 베이스로 바로 이동할 수 있다.
3. `GameScene`에서 쓰레기를 클릭하면 로봇이 인접 위치까지 경로를 찾아 이동한다.
4. 타이밍에 맞춰 스페이스바를 눌러 QTE를 수행하고 수집물을 획득한다.
5. 탐험 종료 확인창을 거치거나 배터리가 소진되면 `BaseScene`으로 복귀한다.
6. 베이스의 감정 로봇이 수집물을 감정하고 배수에 따른 골드를 지급한다.
7. 골드로 다섯 계열의 업그레이드를 구매한다.
8. 배터리를 충전한 뒤 다시 탐험을 시작한다.

## 업그레이드 트리

### 이동 숙련도

- 구동 보정: 이동 속도 +10%
- 경량 바퀴: 이동 속도 +20%
- 터보 구동: 이동 속도 +40%
- 세 효과는 누적 적용된다.

### 배터리 숙련도

- 절전 회로: 배터리 지속시간 +20%
- 고속 충전: 충전시간 30% 단축
- 고밀도 전지: 최대 배터리 `100 → 150`

### 감정 숙련도

- 센서 보정: 높은 배수 등장 확률 +4%p
- 패턴 학습 II: 높은 배수 등장 확률 추가 +7%p
- 희귀 탐지: 최종 감정 골드 +12%

### 수집 숙련도

- 집게 개선: 평균 수집량 +20%
- 수거 스캐너: QTE 성공 판정 범위 +35%
- 자원 회수: 평균 수집량 추가 +50%
- 수집량의 소수 부분은 확률적 추가 지급으로 처리한다.

### 탐사 숙련도

- 광역 탐지: 쓰레기 생성량 +20% (`5 → 6`)
- 신호 증폭: 상위 등급 쓰레기 생성 가중치 +20%
- 정밀 스캔: 해당 쓰레기 고유 등급 수집물 가중치 +30%

기존 분해 숙련도는 실제 분해 시스템이 없어 탐사 숙련도로 교체했다.

## 영구 저장

`GameSaveSystem`이 단일 로컬 저장 슬롯을 관리한다.

저장 항목:

- 골드
- 감정 전 수집물 ID와 개수
- 업그레이드별 레벨
- 현재 배터리 충전량
- 베이스 도달 여부
- 저장 데이터 버전

저장 시점:

- 5초 간격 자동 저장
- 씬 전환
- 애플리케이션 일시정지
- 게임 종료

타이틀 설정창에서 `데이터 초기화`를 두 번 눌러 진행 데이터를 삭제할 수 있다. 음악·효과음 설정과 탐험 튜토리얼 확인 여부는 별도 `PlayerPrefs`로 유지된다.

WebGL 저장은 브라우저 로컬 저장소에 의존한다. 사이트 데이터 삭제 시 세이브가 사라지며 다른 기기나 브라우저와 동기화되지 않는다.

## UI와 사용자 안내

### 타이틀

- Clean Planet 제목과 테마 배경
- 시작하기 버튼
- 저장된 베이스 도달 기록이 있을 때 베이스 이동 버튼
- 음악/버튼 효과음 조절과 데이터 초기화 설정창

### 탐험

- 배터리 HUD
- 이번 탐험의 종류별 수집물 현황
- 도움말 버튼과 튜토리얼 설명창
- 탐험 종료 버튼과 확인창
- 게임 테마에 맞는 탐험 배경

### 베이스

- 메뉴, 감정 로봇/업그레이드 전환 탭, 배터리, 골드가 겹치지 않도록 배치
- 메뉴에서 타이틀로 돌아가기 제공
- 감정 탱크에는 실제 탐험에서 획득한 수집물만 투입
- 업그레이드 노드 상태를 완료/업그레이드 가능/잠김으로 구분

## 데이터와 경제 흐름

```text
쓰레기 선택
→ 로봇 이동
→ QTE
→ 수집물 저장
→ 베이스 복귀
→ 감정 배수 결정
→ 골드 지급
→ 업그레이드 구매
→ 탐험 능력 강화
```

감정 연출 도중 종료하더라도 수집물이 먼저 사라지지 않도록 골드 지급이 확정되는 시점에 수집물을 차감한다.

## 검증 상태

- Unity 에디터 스크립트 컴파일 성공
- Unity 포함 .NET Framework 4.7.1 참조를 사용한 `Assembly-CSharp.csproj` 빌드 오류 0개
- `git diff --check` 통과
- Map01~Map05 프리팹의 중복 오브젝트 ID와 끊어진 내부 참조가 없음을 확인
- 8개 포탈의 목적지 맵과 진입 지점 연결을 정적으로 대조해 모두 유효함을 확인
- 16개 수집물 에셋이 저장 복원 카탈로그에 각각 한 번씩 연결됨을 확인
- 씬 직렬화 참조와 업그레이드 ID 연결을 정적 확인

Map01~Map05의 포탈 왕복과 맵별 쓰레기 QTE는 사용자 플레이로 기본 동작을 확인했다. 아직 저장 후 브라우저 새로고침, 전체 초기화, 업그레이드별 체감 수치를 자동 검증하는 Play Mode 테스트는 없다.

## 남은 우선 작업

1. 현재 5개 맵을 Stage 1 범위로 확정하고 완료·해금 조건과 베이스의 스테이지 선택 UI를 설계한다.
2. 다섯 맵 포탈 왕복과 맵별 쓰레기 초기화 정책을 Unity Play Mode 자동 테스트로 검증한다.
3. 타이틀부터 업그레이드 후 재탐험까지 전체 루프를 Unity Play Mode와 WebGL에서 회귀 테스트한다.
4. WebGL 새로고침 후 골드·수집물·업그레이드·배터리 복원을 확인한다.
5. 업그레이드 수치와 골드 비용을 실제 플레이 시간 기준으로 밸런싱한다.
6. 임시 버튼 효과음을 최종 AudioClip으로 교체한다.
7. Edit Mode/Play Mode 자동 테스트를 추가하고 CI에 연결한다.
8. 필요하면 로그인 기반 클라우드 저장을 별도 시스템으로 도입한다.
